## Stack

| Layer | Technologies |
|---|---|
| Frontend | Next.js 16, React 19, Tailwind CSS, shadcn/ui, Zustand |
| Backend | Next.js Server Actions, Hono.js, Prisma 7, PostgreSQL |
| Auth | Better Auth (email, OAuth, 2FA, API keys) |
| Jobs | Inngest (resumable pipeline) |
| AI | Multi-provider AI SDK + MCP |
| Infra | Docker, Traefik, SSE, WebSocket |

## Deployment flow

```
Git Push → Webhook → Inngest pipeline → Docker API → Container + Traefik route
```

## Real-time flow

```
Docker events → State Manager → SSE → Zustand store → React interface
```

```
nexploy/
├── apps/

```

## Pipeline nodes are a separate library

Nodes do not live in the application repository. They form a standalone library,
**nexploy-nodes**, that Nexploy consumes.

```
nexploy-nodes/
└── packages/
    ├── node-core/   # Contracts, Zod schemas, execution helpers — no dependencies
    ├── node-ui/     # UI adapter, drag-and-drop primitives, theme
    └── nodes/       # The 62 built-in nodes
```

Every node is a single self-describing folder:

```
packages/nodes/src/deploy-compose/
├── node.ts        # descriptor — the source of truth
├── executor.ts    # server-side logic
├── Config.tsx     # configuration panel
└── locales/       # name, description and labels (en, fr)
```

The **descriptor** is isomorphic: no React, no icons, no canvas dependency. Everything
else is derived from it — the interface definition, the colour and icon that follow the
category, the catalogue exposed to the AI assistant, and the outputs you can drag onto a
downstream node. Nothing is declared twice.

A node never reaches into the application. What it needs is **injected**:

| Side | Access |
|---|---|
| Executor | `ctx.services.docker`, `.git`, `.build`, `.registry`, `.domain`, `.ssl`, `.version`… |
| Panel | Hooks from `@nexploy/node-ui` — environments, containers, images, volumes, networks |

That inversion is what makes the library reusable: the same node definition works under
any host that provides those services.

<Callout>
A node type is a free-form string, not a closed enum. A node is valid because a descriptor
is registered for it — which is what opens the door to third-party nodes.
</Callout>
