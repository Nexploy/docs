---
title: Environment variables
description: Reference of Nexploy environment variables
---

In production via the installer (`install.sh`), all of these variables are generated automatically and passed directly to each container at startup — none of them are written to a file on the host (inspect them with `docker inspect nexploy_app` / `docker inspect nexploy_docker_api`). In development, they're configured in `apps/nexploy/.env` and `apps/docker-api/.env` (see [Installation](/getting-started/installation)).

Only `nexploy-cli` (the recovery tool, separate from the application) persists anything on the host, in `/etc/nexploy/cli.env`: its recovery key hash — see [Recovery CLI](/security/recovery-cli).

## `apps/nexploy/.env`

| Variable | Purpose |
|---|---|
| `NEXPLOY_URL` | Public URL of the app (Inngest realtime, internal AI calls, etc.) |
| `NEXPLOY_PORT` | Port the custom Next.js server listens on (default `3000`) |
| `BETTER_AUTH_SECRET` | Secret used to sign sessions — no default, generate with `openssl rand -hex 32` |
| `BETTER_AUTH_URL` | Base URL Better Auth uses for callbacks/cookies |
| `TRUSTED_ORIGINS` | Comma-separated list of extra trusted origins (optional) |
| `DATABASE_URL` | PostgreSQL connection string |
| `ENCRYPTION_KEY` | Secret the AES-256-GCM env-variable key is derived from (scrypt) — no default, generate with `openssl rand -hex 32` |
| `DOCKER_API_URL` | URL of the `docker-api` service |
| `NEXPLOY_API_KEY` | Key sent as `Authorization: Bearer` to `docker-api` to authenticate — generated by `pnpm db:seed`, same value as `NEXPLOY_API_KEY` on the docker-api side |
| `INNGEST_BASE_URL` | URL of the self-hosted Inngest server (SDK sends events / syncs functions there) |
| `INNGEST_EVENT_KEY` | Inngest event key |
| `INNGEST_SIGNING_KEY` | Inngest signing key (verifies requests between the app and the Inngest server) |
| `DEPLOYER_WORK_DIR` | Working directory for cloning repos and building images |
| `TRAEFIK_SERVICE_DIR` | Host directory of the Traefik file provider (optional, containerized deployments) |
| `TRAEFIK_CERTS_CONTAINER_PATH` | Path to TLS certs inside the Traefik container (optional) |
| `TRAEFIK_STATIC_CONFIG_PATH` | Where to write `traefik.yml` on first boot if it doesn't exist (optional — only enables rendering on `install.sh` installs) |
| `TRAEFIK_USE_TLS` | `false` to render `traefik.yml` without HTTPS/ACME (IP mode, no domain) — defaults to `true` |
| `ACME_EMAIL` | Let's Encrypt email used to render `traefik.yml` when `TRAEFIK_USE_TLS` isn't `false` |
| `NEXPLOY_TLS_MODE` | The instance TLS mode: `letsencrypt`, `custom` or `ip` — inferred from `TRAEFIK_USE_TLS` when unset |
| `NEXPLOY_TLS_CERTIFICATE_ID` | Id of the uploaded certificate to serve when `NEXPLOY_TLS_MODE` is `custom` |
| `DOCKER_SOCKET` | Path to the machine's Docker socket, used as the default *Socket path* for new environments and by `pnpm db:seed` for the local environment. Exposed to the browser as `NEXT_PUBLIC_DOCKER_SOCKET` by `next.config.ts`. Default `/var/run/docker.sock` — Colima: `~/.colima/default/docker.sock`, Docker Desktop macOS: `~/.docker/run/docker.sock` |
| `TRAEFIK_TEMPLATES_DIR` | Directory of the Traefik templates used to render `traefik.yml` (optional — default `<cwd>/traefik-templates`) |
| `HEAP_SOFT_LIMIT_MB` | Heap threshold in MB above which the server triggers a manual GC (optional — default `3200`) |
| `MAX_TURBOPACK_CACHE_GB` | Max Turbopack cache size in GB, cleared on boot above it (development only — default `3`) |
| `LOG_LEVEL` | Log level (e.g. `info`) |
| `NODE_ENV` | Runtime mode — set to `production` by `install.sh` |

## `apps/docker-api/.env`

| Variable | Purpose |
|---|---|
| `PORT` | Listening port (default `3300`) |
| `NODE_ENV` | Runtime mode — set to `production` by `install.sh` |
| `LOG_LEVEL` | Log level |
| `NEXPLOY_DEBUG` | `true` exposes Nexploy's infrastructure resources and lifts every guard on them — **dangerous**, see the warning at the bottom of this page. Set it on the `apps/nexploy/.env` side too |
| `DOCKER_SOCKET` | Path to the Docker socket to drive (default `/var/run/docker.sock`). On Colima or Docker Desktop macOS, point it at the real socket (`~/.colima/default/docker.sock`, `~/.docker/run/docker.sock`) |
| `NEXPLOY_API_URL` | URL of the nexploy app, to call it back |
| `NEXPLOY_API_KEY` | Key sent to the nexploy app to authenticate (loading environments, syncing deletions) — same value as `NEXPLOY_API_KEY` on the nexploy side. If unset, `docker-api` fetches it on its first call via `GET /api/internal/docker-api-key` (authenticated with `ENCRYPTION_KEY`) and keeps it in memory — this is what the Docker images do, don't set it manually there |
| `ENCRYPTION_KEY` | Same value as on the `apps/nexploy/.env` side — sent as `x-internal-secret` to fetch `NEXPLOY_API_KEY` and to have nexploy verify the API keys it receives |
| `TRAEFIK_CONTAINER_NAME` | Name of the Traefik container to manage (default `nexploy_traefik`) |
| `TRAEFIK_NETWORK_NAME` | Docker network Traefik watches (default `nexploy_traefik_network`) |
| `NEXPLOY_APP_CONTAINER_NAME` | Name of the `nexploy_app` container (default `nexploy_app`) — used to recreate it on a domain/IP switch from Admin → Settings |
| `TRAEFIK_STATIC_CONFIG_PATH` | Path to `traefik.yml`, removed then awaited again after a `nexploy_app` container recreation (optional) |
| `DOCKER_API_CONTAINER_NAME` | Name of the `docker-api` container (default `nexploy_docker_api`) — used during instance upgrades |
| `UPGRADER_CONTAINER_NAME` | Name of the throwaway container that runs the instance upgrade (default `nexploy_upgrader`) |
| `NEXPLOY_IMAGE_REPOSITORY` | Image repository pulled for the app during an upgrade (default `nexploy/nexploy`) |
| `DOCKER_API_IMAGE_REPOSITORY` | Image repository pulled for `docker-api` during an upgrade (default `nexploy/docker-api`) |
| `INNGEST_CONTAINER_NAME` | Name of the Inngest container, restarted after an instance upgrade (default `nexploy_inngest`) |
| `POSTGRES_CONTAINER_NAME` | Name of the PostgreSQL container, restarted after an instance upgrade (default `nexploy_postgres`) |
| `NEXPLOY_GITHUB_REPO` | GitHub repository polled to detect new releases (default `Nexploy/nexploy`) |

`SELF_UPGRADE_TARGET_IMAGE`, `SELF_UPGRADE_CONTAINER_NAME`, `SELF_UPGRADE_APP_TARGET_IMAGE` and `SELF_UPGRADE_APP_CONTAINER_NAME` are not configured by hand: `docker-api` injects them itself into the `nexploy_upgrader` container it creates to upgrade itself, and that container reads them back on boot.

## `nexploy_postgres` container

Neither application reads these — they configure the PostgreSQL image itself. `install.sh` passes them to the `nexploy_postgres` container and builds `DATABASE_URL` from them. On `upgrade` it reads them back off the existing container so the database keeps working.

| Variable | Purpose |
|---|---|
| `POSTGRES_DB` | Database created on first boot (`nexploy`) |
| `POSTGRES_USER` | PostgreSQL role created on first boot (`nexploy`) |
| `POSTGRES_PASSWORD` | Password for that role — randomly generated by `install.sh` (in development: `nexploy`) |

<Callout type="warn" title="Keep your ENCRYPTION_KEY safe">
  It is used to decrypt your repository environment variables. Losing it makes your secrets unrecoverable.
</Callout>

<Callout type="warn" title="NEXPLOY_API_KEY must match on both sides">
  It is the **same** variable name and the **same** secret in `apps/nexploy/.env` and `apps/docker-api/.env`. A mismatch between the two makes every call between the two services fail with a `401`. In production, don't set it: `docker-api` fetches it from nexploy.
</Callout>

<Callout type="warn" title="ENCRYPTION_KEY must match on both sides too">
  `docker-api` uses it as the `x-internal-secret` when it calls nexploy back (fetching its API key on the first call, then verifying the API keys it receives). A different value there breaks both.
</Callout>

<Callout type="warn" title="NEXPLOY_DEBUG exposes the instance infrastructure">
  Nexploy hides its own containers (`nexploy_app`, `nexploy_docker_api`, `nexploy_traefik`, `nexploy_postgres`, `nexploy_inngest`, `nexploy_upgrader`), its images (`nexploy/nexploy`, `nexploy/docker-api`), its networks (`nexploy_network`, `nexploy_traefik_network`) and its volumes (`nexploy_db`, `nexploy_traefik_acme`, `nexploy_deployer_workdir`), and refuses every route that would reach them by id.

  `NEXPLOY_DEBUG=true` lifts all of it: they become listable, inspectable and actionable like any other resource. Stopping `nexploy_postgres`, deleting `nexploy_traefik_network` or wiping `nexploy_db` takes the instance down, and deleting the database volume is unrecoverable.

  Keep it for debugging a broken instance, on a machine you can afford to break. It must be set on **both** containers: `docker-api` enforces the guards, and the app enforces one of its own.
</Callout>
