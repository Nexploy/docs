title: Serveur MCP
description: Connecter Cursor, Claude Desktop ou n'importe quel client MCP à votre infrastructure

Au-delà de l'[assistant IA intégré](/features/ai-assistant), Nexploy expose son propre **serveur Model Context Protocol**. N'importe quel client MCP externe — Cursor, Claude Desktop, et d'autres — peut s'y connecter et agir sur votre infrastructure avec les mêmes outils que l'assistant intégré.

Tout se configure depuis **Administration → IA → MCP**.

## Endpoint

Le serveur écoute sur un unique endpoint, affiché sur cette page :

```
https://<votre-domaine>/api/mcp
```

Il parle en HTTP streamable. L'authentification est acceptée soit via une session OAuth (le client est renvoyé vers `/signin`), soit via une clé API.

## Générer une clé

Cliquez sur **Générer une clé API**, donnez-lui un nom identifiant le client (`Cursor`, `Claude Desktop`…), et copiez la clé — elle n'est affichée **qu'une seule fois**. Les clés sont préfixées `nxp_mcp_` et **n'expirent jamais** ; révoquez-les depuis la même page quand un client n'a plus besoin d'accès.

Une clé est rattachée à l'utilisateur qui l'a créée et hérite de ses permissions, d'instance comme d'organisation. En générer une requiert la permission `mcpKey:create`, détenue par le seul rôle d'instance `admin`.

Envoyez-la dans l'en-tête `x-api-key` :

```json
{
  "mcpServers": {
    "nexploy": {
      "url": "https://<votre-domaine>/api/mcp",
      "headers": { "x-api-key": "nxp_mcp_…" }
    }
  }
}
```

## Outils disponibles

68 outils sont exposés, répartis en 12 groupes :

| Groupe | Outils |
|---|---|
| **Conteneurs** (10) | `listContainers`, `inspectContainer`, `getContainerLogs`, `containerAction`, `pauseContainer`, `unpauseContainer`, `renameContainer`, `recreateContainer`, `createContainer`, `execInContainer` |
| **Images** (7) | `listImages`, `inspectImage`, `pullImage`, `tagImage`, `deleteImages`, `pruneImages`, `scanImage` |
| **Volumes** (5) | `listVolumes`, `inspectVolume`, `createVolume`, `deleteVolumes`, `pruneVolumes` |
| **Réseaux** (4) | `listNetworks`, `inspectNetwork`, `createNetwork`, `deleteNetworks` |
| **Compose** (6) | `listComposeStacks`, `getComposeStatus`, `listComposeContainers`, `validateComposeSyntax`, `deployCompose`, `composeAction` |
| **Dépôts** (9) | `listRepositories`, `getRepository`, `listBuilds`, `getBuildNodeLogs`, `triggerRepositoryBuild`, `setEnvVariables`, `cancelBuild`, `removeBuild`, `deleteRepository` |
| **Pipelines** (4) | `listPipelineNodes`, `getPipelineNodeDetail`, `analyzeRepository`, `savePipeline` |
| **Environnements** (6) | `listEnvironments`, `useEnvironment`, `createEnvironment`, `updateEnvironment`, `setDefaultEnvironment`, `deleteEnvironment` |
| **Registries** (4) | `listRegistries`, `createRegistry`, `updateRegistry`, `deleteRegistry` |
| **SSL** (4) | `listSslCertificates`, `createLetsEncryptCertificate`, `createCustomCertificate`, `deleteSslCertificate` |
| **Swarm** (8) | `listSwarmNodes`, `listSwarmServices`, `initSwarm`, `leaveSwarm`, `swarmNodeAction`, `createSwarmService`, `scaleSwarmService`, `removeSwarmServices` |
| **Confirmation** (1) | `requestConfirmation` — l'assistant l'appelle avant toute action destructrice et attend votre accord |

## Restreindre ce qu'il peut faire

Depuis **Administration → IA → Paramètres**, chaque groupe se désactive indépendamment — images, volumes, réseaux, compose, dépôts, registries, SSL, environnements, opérations Swarm, et `execInContainer` à lui seul. Un groupe désactivé n'est tout simplement pas enregistré sur le serveur : le client ne voit même pas ces outils.

Deux interrupteurs au niveau de l'instance comptent particulièrement :

- **Activer le serveur MCP** — désactivé, `/api/mcp` rejette toutes les requêtes et coupe d'un coup tous les clients externes.
- **Exiger une confirmation pour les actions destructives** — activé, un outil `requestConfirmation` est enregistré et le modèle doit l'appeler, puis s'arrêter, avant toute suppression, arrêt ou prune. Vous confirmez avant qu'il ne poursuive.

<Callout type="warn" title="Une clé MCP est une clé Nexploy">
  Les clés API sont adossées à une session : une clé envoyée en `x-api-key` authentifie aussi le reste de l'API Nexploy, pas uniquement `/api/mcp`. Traitez-la comme le mot de passe du compte qui l'a créée.
</Callout>
