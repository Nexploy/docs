---
title: API keys
description: Programmatic access to the Nexploy API
---

Nexploy supports **API keys** for calling its API without an interactive session.

## Where to create them

Keys are generated from **Administration → AI → MCP**, the same page used to connect an external MCP client — see [MCP server](/en/features/mcp-server). There is no other creation screen: a key generated there works for MCP and for the rest of the API alike.

Generating a key requires the `mcpKey:create` permission, held by the `admin` instance role only. A `developer` can see existing keys but cannot create or revoke them.

## Using one

Send the key in the `x-api-key` header:

```bash
curl -H "x-api-key: nxp_mcp_…" https://<your-domain>/api/repositories
```

Keys are **session-backed**: the request is handled exactly as if the user who created the key were signed in. It therefore inherits their instance role **and** their organization memberships — a key created by a user only sees the repositories of their organizations.

## Lifecycle

- The secret is shown **once**, at creation. Only a hash is stored.
- Generated keys are prefixed `nxp_mcp_` and **never expire**.
- Revoke them from the same page; revocation takes effect immediately.
- Deleting the owning user invalidates their keys.

<Callout type="warn" title="A key is worth the account that created it">
  There is no per-key scoping: it grants everything its owner can do, destructive
  actions included. Create them from an account whose permissions match the
  intended use, and revoke them as soon as a tool no longer needs access.
</Callout>

## Not to be confused with

`NEXPLOY_API_KEY`, the key shared between `nexploy` and `docker-api`, is an internal API key of the same mechanism, but it is generated by the seed and managed automatically in production — don't revoke it from this page. See [Environment variables](/en/reference/environment-variables).
