## Login methods

- **Email / password** — the only way to sign in to the application.
- **Two-factor authentication (2FA)** — TOTP with backup codes.
- **API keys** — for programmatic access, see [API keys](/en/security/api-keys).

<Callout type="warn" title="No OAuth login, and no open sign-up">
  Git provider OAuth (GitHub, GitLab, Gitea, Bitbucket, Azure Repos) — a public repository added by custom URL uses no credentials — is only
  used to connect your repositories, not to sign in to Nexploy.
  Open sign-up is disabled: the first admin account
  is created through `/setup`, and every other account from
  **Administration → Users**.
</Callout>

## User management

An admin plugin lets you manage users, their roles and their permissions. Permissions are granular per resource (read/write by object type).

This instance role (`guest`, `developer`, `admin`) authorizes a **type** of action. Access to a specific resource additionally depends on membership of the organization that owns it — see [Organizations](/en/core-concepts/organizations).

## Data security

- **Encrypted environment variables** at rest (AES-256-GCM — authenticated encryption: any tampering with the ciphertext is detected on decryption).
- **OAuth tokens** stored securely with automatic refresh.
- **Webhook secrets** validating callbacks from Git providers.
- **CSRF protection** and session-based authentication.
