## Installation en production (recommandée)

Sur une machine avec Docker, une seule commande suffit :

```bash
curl -fsSL https://nexploy.app/install.sh | sh
```

<Callout>
Rien n'est cloné ni compilé — l'installeur récupère les images publiées (`nexploy/nexploy` et `nexploy/docker-api`), donc une installation prend environ une minute.
</Callout>

Le script installe Docker si besoin, demande votre **domaine** et un **email Let's Encrypt** (ou vous permet de sauter les deux et de tourner sur l'IP nue du serveur en HTTP simple — voir ci-dessous), génère tous les secrets et les passe directement aux conteneurs (rien n'est écrit en clair sur le disque de l'hôte), écrit la configuration Traefik, puis démarre cinq conteneurs :

| Conteneur | Rôle |
|---|---|
| `nexploy_traefik` | Reverse proxy, TLS, ports 80/443 |
| `nexploy_app` | L'application (exécute les migrations et le seed au premier démarrage) |
| `nexploy_docker_api` | Opérations Docker |
| `nexploy_postgres` | Base de données |
| `nexploy_inngest` | Jobs du pipeline de build |

Prérequis : lancer le script en **root** (il gère Docker et écrit dans `/etc/nexploy`), et les ports **80** et **443** libres et accessibles. Si vous utilisez un domaine, le DNS doit pointer vers la machine avant la fin de l'installation — Let's Encrypt utilise un challenge HTTP pour émettre le certificat.

### Installer sans domaine (IP uniquement)

Pas encore de domaine ? Laissez le prompt domaine vide (ou définissez `NEXPLOY_NO_DOMAIN=true` pour une installation non interactive) et l'installeur détecte l'IP publique de votre serveur et sert Nexploy en HTTP simple à la place — pas de Let's Encrypt, pas d'email requis :

```bash
NEXPLOY_NO_DOMAIN=true sh -c "$(curl -fsSL https://nexploy.app/install.sh)"
```

<Callout type="warn">
HTTP simple signifie aucun certificat — pratique pour démarrer, déconseillé sur la durée. Vous pouvez passer à un vrai domaine avec HTTPS à tout moment, soit depuis **Admin → Paramètres** dans l'app (qui recrée le conteneur de l'app et redémarre Traefik avec les nouveaux réglages, sans réinstallation), soit manuellement — voir [Reverse proxy & SSL](/networking/traefik-ssl). Pensez aussi à mettre à jour manuellement l'URL de redirection OAuth chez votre fournisseur git — voir [Reverse proxy & SSL](/networking/traefik-ssl).
</Callout>

### Installation non interactive

```bash
NEXPLOY_DOMAIN=nexploy.example.com NEXPLOY_EMAIL=you@example.com \
  sh -c "$(curl -fsSL https://nexploy.app/install.sh)"
```

| Variable | Défaut | Rôle |
|---|---|---|
| `NEXPLOY_DOMAIN` | *(demandé)* | Domaine sur lequel l'app est servie |
| `NEXPLOY_EMAIL` | *(demandé si un domaine est défini)* | Adresse de contact Let's Encrypt |
| `NEXPLOY_NO_DOMAIN` | `false` | À `true` pour sauter le domaine et servir sur l'IP du serveur (HTTP simple) |
| `NEXPLOY_VERSION` | *(dernière release)* | Tag d'image à déployer, ex. `v1.0.0` |
| `NEXPLOY_DIR` | `/etc/nexploy` | Emplacement des secrets et de la config Traefik |
| `NEXPLOY_REPO` | `Nexploy/nexploy` | Repo GitHub utilisé pour résoudre la dernière release |

### Mise à jour

```bash
curl -fsSL https://nexploy.app/install.sh | sh -s upgrade
```

La mise à jour récupère la version demandée et recrée les conteneurs. Vos secrets, votre base de données et votre domaine restent intacts — relancer l'installeur ne les régénère jamais.

Si vous êtes déjà sur la dernière version, la commande ne fait rien. Pour forcer la recréation des conteneurs même sans changement de version (utile après un problème sur un conteneur, par exemple), ajoutez `--force` :

```bash
curl -fsSL https://nexploy.app/install.sh | sh -s upgrade --force
```

### Désinstaller

```bash
curl -fsSL https://nexploy.app/install.sh | sh -s uninstall
```

<Callout type="warn" title="Destructif">
Cela supprime votre base de données, les métadonnées de vos déploiements et tous les secrets générés — sans possibilité de retour en arrière. Une confirmation en tapant `remove` sera demandée.
</Callout>

### Gérer l'instance

```bash
docker logs -f nexploy_app          # logs de l'application
docker restart nexploy_app          # redémarrer l'app
docker ps --filter name=nexploy_    # tous les conteneurs Nexploy
```

<Callout type="warn" title="Ne supprimez pas les conteneurs sans réfléchir">
  Vos secrets (dont `ENCRYPTION_KEY`, qui sert à déchiffrer vos variables d'environnement) ne sont stockés nulle part sur le disque de l'hôte — ils vivent uniquement dans l'environnement des conteneurs (consultable via `docker inspect nexploy_app`). Supprimer les conteneurs sans avoir sauvegardé ces valeurs les rend irrécupérables. Seul `/etc/nexploy/cli.env` persiste sur disque, et ne contient que le hash de la recovery key de `nexploy-cli` — voir [CLI de recovery](/security/recovery-cli).
</Callout>

## Installation en développement

### 1. Prérequis et installation des dépendances

```bash
corepack enable
node -v   # doit être >= 22.13

git clone https://github.com/Nexploy/nexploy.git
cd nexploy
pnpm install
```

### 2. Créer les fichiers d'environnement

```bash
cp apps/nexploy/.env.example    apps/nexploy/.env
cp apps/docker-api/.env.example apps/docker-api/.env
```

Deux secrets n'ont pas de valeur par défaut — générez-les et collez-les dans `apps/nexploy/.env` :

```bash
openssl rand -hex 32   # -> BETTER_AUTH_SECRET
openssl rand -hex 32   # -> ENCRYPTION_KEY
```

`ENCRYPTION_KEY` va aussi dans `apps/docker-api/.env`, avec la **même valeur** — docker-api l'utilise comme secret interne pour rappeler nexploy et vérifier les clés API.

Toutes les autres valeurs pointent déjà vers la stack de dev (PostgreSQL sur `5433`, Inngest sur `8288`). Laissez `NEXPLOY_API_KEY` vide dans les deux fichiers pour l'instant — l'étape 5 la génère.

### 3. Démarrer l'infrastructure

```bash
docker compose -f infra/docker/docker-compose.dev.yml up -d
```

| Conteneur | Port | Notes |
|---|---|---|
| PostgreSQL | `5433` | utilisateur / mot de passe / base : `nexploy` |
| Inngest dev server | `8288` | UI pour inspecter les jobs de build |
| Traefik | `80`, `443`, `8080` | `8080` est le dashboard |

### 4. Appliquer les migrations de la base de données

```bash
pnpm --filter=nexploy db:migrate:dev
```

### 5. Seed et clé API interne

Nexploy et `docker-api` s'authentifient l'un l'autre via une **clé API Better Auth** partagée. Le seed la crée — avec l'environnement Docker local par défaut — et l'affiche :

```bash
pnpm --filter=nexploy db:seed
```

```
NEXPLOY_API_KEY=nxp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Copiez cette valeur dans **les deux** fichiers d'environnement :

```bash
# apps/nexploy/.env      — la clé que nexploy envoie à docker-api
NEXPLOY_API_KEY=nxp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

# apps/docker-api/.env   — la clé que docker-api attend, et utilise pour rappeler nexploy
NEXPLOY_API_KEY=nxp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

Les deux côtés la lisent depuis le **même nom de variable**, `NEXPLOY_API_KEY`.

<Callout type="warn">
Relancer le seed **révoque et recrée** la clé. Si `docker-api` répond soudainement `401`, recopiez-la.
</Callout>

### 6. Démarrer les applications

```bash
pnpm dev
```

| Service | URL |
|---|---|
| Application web | http://localhost:3000 |
| Docker API | http://localhost:3300 |
| Inngest Dev UI | http://localhost:8288 |
| Traefik Dashboard | http://localhost:8080 |

Ouvrez http://localhost:3000 — vous êtes redirigé vers `/setup`, où vous créez le premier compte administrateur.
